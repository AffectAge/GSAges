# Здания, население и рынки

Один ход — год. `Economy.gs` выполняется после демографии (875), перед отчётами.
Все вычисления идут в памяти. Новые товары доступны для продажи только в следующем году.
Это самостоятельная базовая модель рынков по обсуждённым правилам, не воспроизведение всех формул Victoria 3.

## Подготовка книги

Меню **Игровой движок → Подготовить здания и рынки** (`INITIALIZE_BUILDING_ECONOMY`).
Команда добавляет отсутствующие столбцы к именованному диапазону `Игровые_данные`,
вставляя новые столбцы справа от него, чтобы сохранить соседние данные.
Повторный запуск не заменяет заполненные каталоги. Команда не создаёт здания, страны или деньги и не запускает ход.
Начальные шаблоны и товары редактируются в `ECONOMY_STARTER_CATALOG` в `EconomySetup.gs`;
после подготовки реальные правила берутся из столбцов книги.

Новые столбцы: `Здания`, `Шаблоны зданий`, `Товары`, `Страны`, `Рынки`, `Торговые отношения`.
Каждая непустая ячейка содержит JSON-массив записей. Несколько записей могут занимать одну ячейку;
при обработке записи автоматически перепаковываются целиком. Положение строки не определяет провинцию.
`Провинции` сохраняет прежний формат: один объект в ячейке. `Население` — массивы групп.

Если столбца `Здания` нет или он пуст, экономика не активируется. При наличии зданий обязательны
все столбцы настройки, записи существующих стран-владельцев и корректные ссылки на шаблоны/товары/рынки.
Отсутствующий ownerId, null, пустая строка или «NULL» означают ничейную провинцию: демография
продолжается, доступная рабочая сила для экономики равна нулю, здания приостановлены с причиной
«Нет владельца провинции». Они не торгуют, не добывают и не получают субсидии; деньги и склады
сохраняются. Неизвестный непустой ID владельца остаётся ошибкой данных.
Отсутствие маршрута или материалов — игровая остановка здания; неизвестная ссылка — ошибка данных и отмена хода.

## Минимальные данные

В `Страны`:
```json
[{"id":"ITA","marketId":"italian_market","treasury":100000,"workerCoefficients":{"men":0.5,"women":0.3},"subsidies":{"budget":10000,"templateIds":["transport_hub"]}}]
```
В `Рынки`:
```json
[{"id":"italian_market","prices":{}}]
```
`marketId` страны определяет членство; для общего рынка у стран одинаковый идентификатор.
Казна, коэффициенты и бюджеты — игровые настройки, приведённые значения только пример.

В существующую провинцию добавьте транспорт, сохраняя остальные поля:
```json
"transport":{"baseCapacity":10000,"tariff":0.01,"buildingCapacity":0}
```
Соседи задаются существующим массивом `neighbors`. Рёбра направленные: для двустороннего пути
соседство указывается с обеих сторон. Ссылки на отсутствующие соседние провинции игнорируются.
`buildingCapacity` — вклад работающих транспортных зданий прошлого хода. Первоначально задайте 0
или обоснованную стартовую мощность. После расчёта поле обновляется для следующего года.
Транспортное здание не получает транспортные платежи: их получает казна, поэтому ему могут понадобиться субсидии.

Пример ручного здания в столбце `Здания` (замените provinceId на существующий):
```json
[{"id":"mine_1","provinceId":1,"templateId":"iron_mine","level":1,"enabled":true,"priority":10,"money":20000,"inventory":{"tools":20},"salaries":{},"employment":[]}]
```
На провинцию допускается одна запись каждого шаблона; расширение задаётся `level`.
Чем выше численный `priority`, тем раньше доступ к дефициту.
Начальные деньги и товары задаются вручную. Команда подготовки их не выдаёт.
Шаблоны содержат стартовые зарплаты, число рабочих, входные/выходные товары, источники добычи,
вместимость склада, условия, модификаторы эффективности и необязательную `transportCapacity`.
Все нормы указаны на один уровень за год. Нулевое число рабочих допустимо для тестов/особых зданий.

## Природные ресурсы

Конечный запас:
```json
{"id":"Железная руда","type":"Железная руда","mode":"finite","amount":125000}
```
Существующие записи `{type, amount}` поддерживаются: type служит ID, режим — finite.

Возобновляемый запас:
```json
{"id":"forest","type":"Лес","mode":"renewable","amount":10000,"maxAmount":15000,"regeneration":500}
```
Восстановление происходит после добычи, один раз за год.

Годовая производительность:
```json
{"id":"farmland","type":"Сельхозземля","mode":"annual","annualCapacity":5000}
```
Лимит общий для зданий провинции и заново доступен каждый год. Плодородие и климат могут менять
эффективность через условия шаблона; annualCapacity автоматически из площади не выводится.
`extraction` расходует источник, `outputs` создаёт товар: выпуск не удваивается.
Источники конкурирующих зданий одного приоритета распределяются пропорционально планам.

## Условия

В `requirements` доступны вложенные `all`, `any`, `not`; в листьях — `field` с операторами
`eq`, `ne`, `in`, `gt`, `gte`, `lt`, `lte`, `between` или `resourceId` с `operator:"available"`.
Поле может быть вложенным (`transport.baseCapacity`). Неизвестный оператор отменяет ход.
Используйте существующие русские значения ландшафта/территории: `Суша`, `Остров`, `Горы` и т.д.

```json
{"all":[{"any":[{"field":"terrainType","operator":"eq","value":"Суша"},{"field":"terrainType","operator":"eq","value":"Остров"}]},{"not":{"field":"radiation","operator":"gt","value":10}},{"resourceId":"Железная руда","operator":"available"}]}
```
`efficiencyModifiers`: массив `{when:условие,multiplier:0.8}`. Совпавшие коэффициенты перемножаются.
Эффективность изменяет выпуск, добычу и транспортный вклад при том же потреблении материалов/труда.
Частичная обеспеченность отдельно изменяет потребление и выпуск пропорционально мощности.

## Труд и деньги

Рабочая сила группы: `floor(men × коэффициент мужчин) + floor(women × коэффициент женщин)`.
В `workforce` сохраняются available, free и byProfession; в `money` — общий денежный баланс группы.
Занятость зданий хранит populationId, profession и целое count. При найме профессия присваивается сразу.
Каждый год найм пересчитывается по актуальному населению: сначала приоритет, затем зарплата;
при равных предложениях пропорционально потребностям, остаток целых рабочих — по стабильному ID.
Рабочие освобождаются из-за отсутствия ресурсов, материалов или денег и распределяются заново в том же ходе.

Зарплата указана за одного работника за год. Базовая — минимум. При убытке она снижается на salaryStep;
при прибыли и нехватке работников повышается на salaryStep. Дефицит при отсутствии прибыли повышения не вызывает.
Субсидии — безвозвратные выплаты, ограниченные политикой страны и казной. Оценка потребности включает
зарплаты и материалы по рыночной цене, но не гарантирует покрытие всех тарифов доставки.
Долги запрещены. Материалы на складах не переоцениваются как бухгалтерская себестоимость:
lastTurn.expenses — денежные расходы этого года, revenue — денежная выручка.

## Торговля и цены

Здание запрашивает входные товары на год полной работы, вычитая свои остатки.
На продажу доступны начальные запасы сверх собственного годового резерва. Новые покупки не перепродаются в этом году.
Цена сделки — текущая цена рынка продавца; покупатель выбирает минимальную полную цену с доставкой и пошлинами.
Цены пересчитываются для следующего года по заявленному спросу и начальным предложениям:
`oldPrice × (1 + priceSpeed × (demand − supply) / max(demand, supply, 1))`.
Итог ограничен minPriceFactor/maxPriceFactor от базовой цены.
Для международной сделки применяются цена продавца и спрос/предложение собственных рынков;
единого мирового балансирующего расчёта нет.

Между разными странами нужны две направленные записи отношений:
```json
[{"from":"ITA","to":"FRA","tradeAllowed":true,"embargo":false,"transitAllowed":true,"importTariff":0.1,"exportTariff":0},
 {"from":"FRA","to":"ITA","tradeAllowed":true,"embargo":false,"transitAllowed":true,"importTariff":0.05,"exportTariff":0}]
```
Ставки — доли цены товара. Импортная пошлина берётся из записи покупателя к продавцу,
экспортная — из записи продавца к покупателю. В общем рынке пошлины отсутствуют; эмбарго сохраняет силу.
Транзит через третью страну требует разрешения от владельца транзитной провинции к стране покупателя.

Вес перевозки: количество × transportWeight. Мощность расходуется во всех провинциях пути,
включая отправителя и получателя. Тариф — деньги за единицу веса в провинции.
Маршрут выбирается по минимальной сумме тарифов среди доступных направленных соседних провинций;
при заполнении участка ищется альтернативный маршрут. Морские провинции работают тем же способом,
но отдельной системы портов/конвоев пока нет.

Распределение сделок выполняется ограниченными раундами (32) с пропорциональными квотами одинакового
приоритета. Это последовательный алгоритм, не глобальная оптимизация всех торговых потоков;
сложные сочетания нескольких маршрутов/товаров могут оставлять неиспользованную мощность.

## Проверки и сохранение

Склады измеряются transportWeight и растут с уровнем. Учитывается место, освобождаемое потреблением.
Деньги, количества товаров, ресурсы и мощности — конечные неотрицательные числа;
население, рабочие и уровни — безопасные целые. Товары могут иметь дробные количества.
Перед записью все новые массивы упаковываются в ячейки ≤48000 символов.
Переполнение, неизвестная ссылка или неверная настройка отменяют ход и попадают в журнал движка.
Успешный ход добавляет отчёт по каждому зданию (мощность, доходы, расходы, причины ограничений).
Предварительные ошибки не записывают игровые данные; сбои API во время нескольких записей
Google Sheets не обеспечивают транзакционного отката.

Проверки: `node tests/population.test.cjs` и `node tests/economy.test.cjs`.
Запуск реального хода для проверки меняет игру — установка кода сама его не запускает.
