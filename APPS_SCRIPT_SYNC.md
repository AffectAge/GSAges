# Автоматическое обновление Google Apps Script

Целевой проект: `1ArxSXXuUjy5th8-M2DQ7Gl9TOD6QFXmxk1XZMkHyaG-B-K7Mhq8qyfrS`.
Книга: https://docs.google.com/spreadsheets/d/1vEnHj_GlnEdubqIx4KLltJly2HeYcYSYN1I_wD5C8-g/edit

После включения каждый коммит с изменениями корневых `.gs` в `civ` загружает код в существующий проект.
Также доступен ручной запуск в Actions → Sync Google Apps Script → Run workflow.

## Один раз включить доступ

1. Войти в Google под владельцем проекта и включить Google Apps Script API:
   https://script.google.com/home/usersettings
2. На своём компьютере с Node.js 22 выполнить:
   ```sh
   npm install --global @google/clasp@3.4.1
   clasp login
   ```
   Выбрать Google-аккаунт, имеющий право редактировать указанный проект.
3. Открыть файл `.clasprc.json` в домашней папке пользователя.
   В GitHub открыть Settings → Secrets and variables → Actions → New repository secret.
   Имя: `CLASPRC_JSON`. Значение: полное содержимое этого файла.
   Не публиковать файл в репозитории и не отправлять в чат: он содержит авторизацию Google.
4. После слияния этой настройки в `civ` запустить workflow вручную.
   Успешный результат — зелёный запуск со стадией обновления кода.

Авторизация хранится в GitHub Secrets и создаётся только в домашней папке временного runner.
При истечении или отзыве доступа нужно повторить `clasp login` и обновить secret.
Отсутствие secret останавливает запуск до обращения к проекту.

## Что происходит при обновлении

- Сначала скачивается текущий проект. Его `appsscript.json` и HTML сохраняются.
- Проверяется ID проекта и синтаксис каждого файла, а также общие объявления всех файлов.
- Если есть `.gs` или `.js`, которых нет в GitHub, загрузка останавливается. Это относится
  и к стандартному файлу `Code`: сначала надо проверить его и перенести нужный код
  в репозиторий либо удалить ненужный файл в редакторе.
- Перед заменой кода создаётся версия текущего проекта Google для восстановления.
  Если создание версии не удалось, обновление не запускается.
- Корневые `.gs` становятся актуальным кодом проекта. Менять управляемый код следует
  в GitHub: ручные правки одноимённых файлов в Apps Script будут перезаписаны.
- Загрузка не запускает игровые функции и не записывает данные в ячейки.
  Существующие триггеры будут использовать новый код при последующих запусках.
  Для версионированных web app deployments требуется отдельное обновление deployment.

Первое подключение нужно проверить на отсутствие выполняющегося игрового хода.
При удалении/переименовании файла в GitHub прежний файл вызовет остановку синхронизации:
это требует явного согласования, чтобы случайно не удалить удалённый код.

## Проверки и ограничения

Проверки локального синтаксиса не заменяют игровой тест в Google Таблицах.
При первичной настройке следует подтвердить, что целевой проект связан именно с указанной книгой:
по одной ссылке невозможно проверить parentId без авторизованного доступа.
До добавления secret и успешного запуска workflow автоматическая связь не активна.
